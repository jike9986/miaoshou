# 商品入库标准 & 仓库→采集箱 校验规范

> 负责人 2026-11-04 定稿。任何商品必须**全部满足**下列条款才能入库；
> 入库后必须**全部满足**才能认领到采集箱。
> 校验器：`server/scripts/product_standard.py`（逐件比对，不通过不入库/不认领）

---

## 一、入库标准（写入 products 表时必须满足）

### 1. 标题 title
| 项 | 标准 |
|---|---|
| 非空 | 必填，`len(strip) >= 4` |
| 禁止占位 | 不得为 `A`、`a`、`test`、`Test`、纯符号、纯数字 |
| 语言 | 与站点一致（MY 站用马来语/英语），**不得混入中文** |
| 长度 | ≤ 255 字符 |
| 兜底 | 上游无有效标题时退到 `oriTitle`；仍无则标 `needsRecollect`，**不猜** |

### 2. 图片
| 项 | 标准 |
|---|---|
| 主图 `imgUrls` | 1 ≤ 数量 ≤ 9，全部可访问（HTTP 200） |
| 详情图 `notes` 内图片 | 0 ≤ 数量 ≤ 9 |
| SKU 图 | 每个颜色值必须有图（`imageUrl` 或 `imgUrls`） |
| 存储 | 全部指向自有图床 `aohuang888.com`，不依赖 1688 CDN |
| 去重 | 同一 URL 不得重复出现 |

### 3. 类目
| 项 | 标准 |
|---|---|
| `cid` | 必填，且必须是目标站点**叶子类目**（`isLastLevel=1`） |
| 站点匹配 | `site` 必须与店铺站点一致 |
| 父级处理 | 父级类目自动下沉到第一个可用叶子类目 |

### 4. 价格
| 项 | 标准 |
|---|---|
| `originPrice` | 采购价（CNY），必填，> 0 |
| `price` | = `originPrice / 汇率`（MYR），汇率取 1.2~2.2 区间内的实际值 |
| `priceIncludeVat` | = **成本价 + 2.00 MYR**（负责人定：微微加价即可，发布时另套定价模板） |
| 下限 | `priceIncludeVat` 必须 ≥ 妙手成本线（跨境运费+关税+增值税） |
| 一致性 | 同一商品所有 SKU 价格策略一致 |

### 5. 包裹尺寸
| 项 | 标准 |
|---|---|
| `packageLength/Width/Height` | 必填，均 > 0，单位 cm |
| 按品类基准 | 运动鞋 33×22×12；轮滑/旱冰 35×24×14；运动拖鞋 33×22×12；运动服饰 30×24×6 |
| 合理性 | 最长边 ≤ 80cm，三边和 ≤ 150cm |

### 6. 重量
| 项 | 标准 |
|---|---|
| `weight` | 必填，> 0，单位 kg |
| 来源优先级 | ① payload.weight ② SKU weight 中位数 ③ 品类默认值（并标记「估算」） |
| 下限 | ≥ 0.4kg（低于则按品类补到基准） |
| 品类上限 | 普通鞋 ≤ 1.2kg；暴走/轮滑/旱冰 ≤ 1.5kg；服饰 ≤ 1.2kg |
| 超限处理 | 超过上限压到上限，并记 `weightBeforeCap` 便于追溯 |

### 7. 规格（SKU）
| 项 | 标准 |
|---|---|
| `skuPropertyList` | 必填，1~3 个维度 |
| 每维度 `propName` | 必填，非空（颜色/尺码） |
| 每维度 `propId` | 必填（颜色 1000000001 / 尺码 1000000002） |
| `attrValueList` | 每维度 ≥ 1 个值，`attrValue` 非空且 ≤ 60 字符 |
| **值唯一性** | 同一维度内 `attrValue` **不得重复**（妙手会报「选项名称重复」） |
| `skuMap` key | 段顺序必须与 `skuPropertyList` 维度顺序一致 |
| **引用完整性** | `skuMap` key 里每个 `attrValueId` 必须能在 `skuPropertyList` 找到 |
| `itemNum` | ≤ 50 字符（妙手硬限制） |
| `stock` | 必填，≥ 0 |
| SKU weight | 必填，> 0 |

### 8. 其他必填
| 字段 | 标准 |
|---|---|
| `isCodOpen` | **字符串** `"0"` 或 `"1"`（布尔值会被妙手拒） |
| `notes` | 描述非空（缺则用标题兜底） |
| `shopId` | 整数，目标店铺 |
| `deliveryOptionSetType` | `"default"`（上游必填） |

## 二、仓库→采集箱 认领标准

### 流程（两步，负责人定）
1. **查公共采集箱**：有 `status ∈ {success, skip}` 的商品 → 直接用，**不采集**
2. **没有** → 采集一次（链接池取一条）→ 等就绪 → 得到 `commonId`
3. 之后**整批复用同一个 `commonId`**，循环复制 N 份，每份立刻覆盖

### 关键约束
| 项 | 要求 |
|---|---|
| `serialNumber` | **无效**，要 N 份就调 N 次，每次 1 |
| 采集就绪判定 | 查**列表接口** `detailList[].status`，不是详情接口 |
| 预取缓存 | `commonId` / `warehouseId` / `categoryTree` 整批只查一次 |
| 复制与覆盖 | **并行**（复制一份立刻覆盖，不等全部复制完） |
| 读回核验 | 认领场景**不做**（每件多花 6s 且必然报不一致） |
| 失败清理 | 覆盖失败的临时载体必须删除，不留脏数据 |

### 认领前必须逐件校验
调用上游之前，先用 `product_standard.validate()` 检查，**不通过直接跳过并报告**，
不允许带着坏数据打上游（那样只会得到一堆看不懂的上游报错）。

## 三、性能基准（实测）
| 场景 | 耗时 |
|---|---|
| 整批预取（公共箱+仓库+类目树） | ~3.7s（一次性） |
| 单件复制 | 2.7~3.2s |
| 单件覆盖 | 3.0~3.2s |
| **单件合计（并行）** | **~5s** |
| 原实现（每件重复查询） | ~20s |

## 四、判定结论
| 结果 | 含义 |
|---|---|
| `ok` | 全部达标，可入库 / 可认领 |
| `needsRecollect` | 上游数据已删或关键字段缺失，**必须重新采集** |
| `fixable` | 有明确修复规则（如价格+2、图片裁剪），自动修 |
| `blocked` | 数据自相矛盾（如重复属性值全被引用），人工处理 |
