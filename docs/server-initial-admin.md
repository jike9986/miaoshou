# 服务器首次最高权限账号

首次部署后，最高权限账号只能由有服务器 shell 权限的运维人员在服务器本机初始化。客户端共享令牌和公开 HTTP 接口不能创建最高权限账号。

## 初始化

1. 先备份数据库，并确认应用已停止写入或已安排维护窗口。
2. 以运行应用的服务账号登录服务器，进入包含 `server/` 和部署 `.env` 配置的发布目录。脚本必须读取与服务相同的 `AOHUANG_DATA_DIR`、`AOHUANG_DATABASE_URL` 等环境配置。PostgreSQL 必须先由运维人员升级至当前 Alembic head；脚本不会自动迁移 PostgreSQL。
3. 使用项目 Python 环境运行：

   ```sh
   cd /opt/miaoshou-listing-v2
   .venv/bin/python server/scripts/init_superadmin.py
   ```

   如果部署使用 systemd 环境文件，应由服务账号在受控 shell 中安全加载该文件后执行脚本；不要把数据库连接串或密码写到命令行参数、工单、终端录屏或聊天记录里。运行前脚本会显示已隐藏数据库密码的目标连接信息，并要求输入 `INIT ADMIN`。

4. 按提示输入用户名和邮箱，并在隐藏输入框中输入两次密码。密码不会回显；脚本不打印 bearer token。初始化成功后，使用该用户名或邮箱与密码通过软件登录。

## 安全行为

- 脚本没有 HTTP 路由，也不接受命令行密码；它只使用应用配置的数据库、迁移校验、用户名/邮箱校验和现有 scrypt 密码哈希。
- PostgreSQL 使用事务级 advisory lock 串行化并发初始化；SQLite 使用写事务锁。已有最高权限账号（包括兼任最高权限的旧版老师账号）时，脚本拒绝修改，不覆盖、不重置任何账号。
- 账号创建在单个事务内完成。发生校验或数据库错误时会回滚；输出不包含 bearer token、数据库密码或异常堆栈。
- 初始化时填写的管理员邮箱尚未验证。首次登录后先完成邮箱验证，再使用密码找回流程；不要再次运行初始化脚本，也不要通过共享客户端令牌提权。

邮件验证码的实际投递取决于部署环境中的 SMTP 配置。本地脚本测试不会验证外部邮件投递。
