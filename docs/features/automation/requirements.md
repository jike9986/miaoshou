# 自动化处理 · 需求说明

## 功能描述

用户在采集箱选择一批商品，启动"自动化处理"，系统自动完成：
1. 从妙手读取商品详情 → 写入 `automation_result` 草稿
2. 翻译商品图片上的文字（调图片翻译 API）
3. 处理完成的商品出现在成品仓库的"自动化结果"标签页
4. 用户在自动化结果里校对/编辑，确认后发布到妙手

---

## 用户角色

- **学员**：只能看自己的运行，不显示"并行件数"设置项
- **管理员**：可以看所有运行，可以配置并行件数

---

## 核心流程（用户视角）

```
采集箱 → 勾选商品 → 点"自动化处理" → 配置弹窗（并行数等）
→ 确认 → 创建运行（AutomationRun）→ 进度面板实时显示
→ 文字处理完毕 → 图片处理完毕 → 运行变"完成"
→ 成品仓库/自动化结果 页面出现这批商品
→ 用户在此校对/编辑/发布
```

---

## 验收标准

1. 批次进度条 = `(文字进度 + 图片进度) / 2`，两者都到 100% 才显示"完成"
2. 无需图片翻译时（`imagePlanned = 0`），图片进度视为 100%，批次不卡在 50%
3. 运行结束后，成品仓库自动刷新，不需要用户手动刷新页面
4. 在自动化结果里编辑商品（图片/重量/尺寸/分类/标题）后，商品不能消失
5. 失败的商品可以在同一次运行里重试，不报"该商品已开始"错误
6. 执行历史状态与进度面板状态保持一致
7. 鼠标滚轮在自动化结果页面不会触发页面缩放
8. SKU 颜色/尺码显示正确的中文标签，不显示 hex ID

---

## 状态定义

### AutomationRun（运行）
| 状态 | 含义 |
|---|---|
| `pending` | 刚创建，未开始 |
| `running` | 正在处理 |
| `completed` | 全部完成（含图片） |
| `failed` | 整体失败 |

### AutomationRunItem（单商品）
| 状态 | 含义 |
|---|---|
| `queued` | 排队中 |
| `running` | 处理中 |
| `succeeded` | 文字处理成功 |
| `needs_review` | 需要人工确认 |
| `failed` | 失败 |

---

## 已知限制

- 图片翻译异步进行，处理中途关闭应用不影响服务器端图片任务
- 同一商品在同一运行里只处理一次（相同 `key` 去重），但可以跨运行重新处理
- 生产服务器用 PostgreSQL，开发用 SQLite，迁移文件必须两者兼容
