## 本版核心：价格口径 + 认领修复

### 负责人定的口径（原话）

> 「成品仓库里面的价格是不能套模板的，就是拿货价，然后只有发布才套模板」
> 「认领到采集箱不是拿货价增一点点，比如 23 就 27、28 人民币」
> 「只需要微微上挑让他不报成本不够就行了」
> 「我还会在妙手重新套用模板改价」
> 「其他国家也是一样的」（指认领失败）

### 落地规则

```
成品仓库  = 拿货价（originPrice），不套模板
认领      = 拿货价 × CLAIM_PRICE_BUMP(1.18)，**人民币层面**
            23 CNY → 27.14 CNY → 16.70 MYR（汇率 1.6255）
妙手嫌低  = 抬到它报的成本线 + 0.01，只多一分
发布      = 才套定价模板（publish_service._repricing）
```

### 五处改动

| 文件 | 改了什么 |
|---|---|
| `warehouse_service.py` | 入库只记拿货价；新增 `_price_warehouse_at_purchase` |
| `collect_box_service.py` | 认领加价改人民币层面 |

### ★ 最大的坑：成本线正则写死 MYR

```python
# 改前
_COST_FLOOR_VALUE = r"基础成本.*?([0-9.]+)\s*MYR"
# 改后
_COST_FLOOR_VALUE = r"基础成本[^0-9]{0,24}([0-9.]+(?:\.[0-9]+)?)\s*[A-Z]{3}"
```

只有马来店的报错能被识别。PH/TH/VN/SG 全部匹配不上 →
`_raise_price_to_reported_floor` 第一行就 `return None` → 抬价逻辑等于不存在。

现场：李小芳往菲律宾店 `19990473` 认领 9 件连败三批
（`clm_9c9c547a1d29` / `clm_a38b29e62394` / `clm_8cd472f819af`）。

### 妙手成本线是什么

严格按重量线性，等于我们菲律宾模板的跨境运费表（450 PHP/kg）：

| 重量 | 妙手报的成本 | 模板运费表 |
|---|---|---|
| 0.5 kg | 225.50 PHP | 225.5 PHP |
| 0.9 kg | 405.50 PHP | 405.5 PHP |
| 1.1 kg | 495.50 PHP | 495.5 PHP |
| 1.2 kg | 540.50 PHP | 540.5 PHP |

分毫不差，不是妙手乱算。低单价商品必然被拦：拿货 8.49 CNY 上挑后 95.89 PHP，
够不到 225.50，必须抬到 225.51。

## 排查方法论（下次直接用）

`.run_diag.py` 把脚本上传服务器执行：

```bash
python .run_diag.py tools/source_match/xxx.py
```

服务器手动跑：

```bash
python - <<'EOF'
import paramiko, pathlib, os
key = str(pathlib.Path.home()/".ssh"/"id_ed25519")
c = paramiko.SSHClient(); c.set_missing_host_key_policy(paramiko.AutoAddPolicy())
c.connect("38.95.75.47", 22, "root", key_filename=key, timeout=40,
          allow_agent=False, look_for_keys=False)
sftp = c.open_sftp(); sftp.put(os.path.abspath("本地.py"), "/tmp/x.py"); sftp.close()
i,o,e = c.exec_command("""set -a; . /etc/aohuang-listing-v2.env; set +a
export PYTHONPATH=/opt/miaoshou-listing-v2/server
PYTHONIOENCODING=utf-8 /opt/miaoshou-listing-v2/venv/bin/python /tmp/x.py 2>&1 | tail -40""", timeout=400)
print(o.read().decode("utf-8","replace") + e.read().decode("utf-8","replace"))
c.close()
EOF
```

**踩过的坑**：
- 脚本事不能叫 `db.py`（和 `db` 包冲突），会 `ModuleNotFoundError: No module named 'db.session'`
- `.run_diag.py` 要在服务器上先 `rm -f /tmp/db.py` 清残留
- `batches` 表的列是 `errors` 不是 `error`
- `products` 表**没有** `weight` 列，重量在 `payload` 里
- `accounts` 表**没有** `deleted_at` 列
- 本地 stdout 打中文/`¥` 会 `UnicodeEncodeError: gbk`，加 `PYTHONIOENCODING=utf-8`
- **nginx 备份不能留在 `sites-enabled/` 里**（2026-11-26 踩到）：
  放个 `aohuang-ai.conf.bak-xxx` 进去，`nginx -t` 直接
  `duplicate upstream "aohuang_ai_3106"` 失败。备份要 `mv` 到 `/root/nginx-backups/`
- 主域 `aohuang888.com` / `.cn` **直连源站，不经 Cloudflare**（响应头是 `Server: nginx`，
  没有 `cf-ray`）；只有 `aohuang888.xyz` 走 CF。所以源站改配置，主域立刻生效，
  `.xyz` 要等缓存过期或 purge

`tools/source_match/_diag_*.py`、`diag_*.py`、`test_sc*.py`

## 发布流程（下次照做）

```bash
# 1. 升版本（四处）
python -X utf8 scripts/check_version.py    # 先看当前

# 2. 构建（必须 pwsh 7，PowerShell 5 解析不了脚本）
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1

# 3. 部署服务器
python scripts/deploy_server.py

# 4. 发 CDN（★ 这一步同时重写固定链接跳转 snippet + reload nginx，

# 5. 校验（★ 会字节级校验「固定链接真正下发的东西」，不只是清单地址）
python -X utf8 scripts/verify_release.py

# 6. 推代码
git push origin master
```

**注意**：`build.ps1` 用 PowerShell 5（`powershell -File`）会报一堆
`Unexpected token` 解析错误，必须用 `pwsh`。

**校验输出怎么看**：

```
清单一致          : OK
清单地址合规      : OK
清单字节一致      : OK      ← 带哈希的文件（自动更新走这条）
固定链接(主域)    : OK      ← 阻塞项，用户被广告出去的链接
固定链接(.xyz CDN): OK/STALE ← 警告项；STALE 时清 CF 缓存即可，不阻塞
```
