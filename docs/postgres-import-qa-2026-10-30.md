# PostgreSQL 导入隔离验收（2026-10-30）

## 范围

本次仅在本机独立 PostgreSQL 16 QA 集群 `server/pg-qa-data-20261030`（`127.0.0.1:55433`）和合成 SQLite 源库上验证迁移脚本。没有连接旧线上服务器或系统 PostgreSQL `55432`。集群自带的 `postgres` 数据库原先已有 18 张应用表，因此未对它执行迁移或导入；验收使用单独创建的 `miaoshou_import_qa_20261030` 和 `miaoshou_rollback_qa_20261030`。

## 结果

- PostgreSQL 目标库和 SQLite 源库分别成功迁移到 Alembic head `20261030_0914`。
- 合成源库包含账号 `41001` 与商品 `42001`。`migrate_sqlite_to_postgres.py --apply` 将 18 张表、2 条业务记录导入空目标库；商品外键仍指向账号 `41001`，JSON SKU 价格读回为 `20.5`。
- 账号凭据在目标库可由 QA 服务密钥解密回原合成明文；源、目标密文 SHA-256 不同，确认导入时执行了重加密。测试密钥只通过临时进程环境变量提供，未写入仓库。
- ORM 自动分配后续 ID 为账号 `41002`、商品 `42002`，外键插入有效。探针事务随后回滚，QA 目标没有留下探针行，说明显式 ID 导入后的序列位置正确。
- 对非空目标再次运行 `--apply` 以非零状态退出并拒绝导入；没有生成第二份备份。
- 独立回滚库通过真实 PostgreSQL 外键约束触发导入异常；检查全部 18 张表后均为 0 行，确认整个导入事务回滚。
- 导入前生成的 SQLite 快照以只读方式检查，`integrity_check` 为 `ok`，外键错误数为 0，并保留预期账号/商品 ID。
- 最终目标库仍只有预期的账号和商品各一条；探针行与失败事务数据均不存在。55433 QA 集群已停止。

## 限制

这些结果只覆盖合成数据和隔离 PostgreSQL 导入路径，不代表生产数据库迁移验收，也没有演练 PostgreSQL 自身的备份与恢复。生产凭据密钥的部署、保管和轮换仍需单独验证。QA 集群、源 SQLite 和备份文件均保留，未纳入 Git。
