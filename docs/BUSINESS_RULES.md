# 关键业务规则

记录不在代码里写明的产品决策，供后续维护时参考。

---

## 采集箱计数

**规则**：采集箱标题显示的 N 是**未发布（notPublished）**状态的产品数量。

**原因**：妙手 API 的 `collect_box_list` 接口不返回 `total` 字段，只返回 `detailList` 数组。  
**实现**：`count_all=True` 模式下，后端扫完所有上游页，累加原始 `detailList` 行数（不过滤 editModel）作为 total。  
**触发条件**：`page=1`，无关键词/店铺/站点过滤，`pageSize ≤ COLLECT_BOX_UPSTREAM_PAGE`。

---

## 仓库可见性

**规则**：学员可以看到成品仓库的全部商品（不按账号过滤），即使该商品是老师用另一个妙手账号入库的。

**原因**：成品仓库是共享货源池，学员的用途是从这里挑货导入自己的采集箱。  
**例外**：未入仓的自动化结果（`automation_result=True`）仍只对来源学员可见。

---

## 重量上限

**规则**：商品原重上限按品类区分，不是统一的一个值。  
暴走/轮滑鞋：2.0 kg；普通鞋：1.5 kg（下限不低于 1.5，即使品类表给的更小）；服饰：1.0 kg。

**原因**：统一用 1.2 kg 卡住会把正常的厚底老爹鞋（1.27 kg）误拦。

---

## 重量增量 vs 原重上限

**规则**：原重上限只比「采集到的上游原始重量」，不加上重量增量一起比。

**原因**：重量增量是上架时报给平台的参数，跟「采集重量是否填错」是两件事。  
若把增量算进去，0.9 kg 的鞋加 0.5 kg 增量后超过 1.2 kg 卡住，属于误拦。

---

## 定价计算

售价计算公式（解「本地展示价」）：

```
售价 = 采购价 + 跨境运费 + 增值税 + 平台佣金 + 支付手续费 + 提现费
     + BCP + SFP + 联盟佣金 + 尾程税 + 平台支持费 + 其他费用 + 利润
```

利润可按售价百分比（`bySalePriceProfit`）或成本百分比（`byCostProfit`）计算。  
`originPrice`（采购价）永远不改，它是成本基准。

---

## 认领互斥

**规则**：同一件商品最近 300 秒内被认领过，第二次认领请求直接拒绝（不管是否同一个人）。

**原因**：妙手 `claim_to_shop` 接口不幂等，重复调用会在采集箱里多一条记录，且没有撤销接口。  
300 秒足够覆盖「同一人连点两次」和「两人前后脚点」，又不会把正常的「过一会儿再认领一次」挡住。

---

## 发布批次状态同步

**规则**：认领批次（`kind=warehouse_claim, mode=publish`）处理完后，批次状态不会自动更新为 done/failed。  
需要在刷新发布日志时调用 `sync_publish_batch_statuses` 触发状态同步。

**原因**：认领流程异步，日志写完时批次可能还没感知到结果。

---

## 图片翻译去重

**规则**：同一张图片（原图内容 + 模型 + prompt + 尺寸四元组的 sha256 相同）不会重复提交，直接复用已有任务结果。

**原因**：防止用户反复提交同一批图消耗额度。  
**例外**：学员（ROLE_MEMBER）的去重 key 还加上 `operator_id + productId`，避免跨人/跨商品复用。

---

## 自注册角色

**规则**：通过 `POST /auth/register` 自注册的账号固定是 `member`（学员）角色，不能自己注册成 teacher/admin。

**原因**：权限提升由管理员在操作员页手动操作。

---

## 采集箱 editModel 过滤

**规则**：`listing_rows()` 只处理 `editModel == None` 或 `"shop"` 的行，跳过站点模式商品。

**原因**：站点模式商品的接口和字段结构不同，不在当前发布流程支持范围内。  
**注意**：`count_all` 模式下 total 用原始 `detailList` 行数（含站点模式），不过滤，贴近妙手界面显示的数字。
